# Browser QA Step 21 — протокол

Середовище: реальний Playwright Chromium у локальному середовищі; frontend `127.0.0.1:5181`, API `127.0.0.1:3011`, PostgreSQL у Docker; використовувалися документовані QA-акаунти. Тестові оголошення та файли створювалися для прогонів і прибиралися тестами. Наявні процеси на портах 3000 і 5173 не зупинялися.

## PASS

- Product та Buy Request: одночасний вибір 8 зображень, обмеження кількості, видалення й повторне додавання у формі, кнопки перестановки, перша фотографія як головна та перетягування мишею. Перевірено ширини 320, 390, 768, 1024, 1280 і 1440 px; горизонтального переповнення в перевірених формах не виявлено. `product-*.png`, `request-*.png`.
- Після зміни lazy loading: редагування та збереження порядку, повторне відкриття і перезавантаження редакторів обох типів. `gallery-final-retry.log`.
- Галереї обох типів: стрілки вперед і назад, лічильник, перехід мініатюрою, збільшення, кнопка закриття і Escape. Окремо перевірені одна фотографія та порожня галерея на 390 px. `product-gallery-final-390.png`, `request-gallery-final-390.png`, `empty-single-test.log`.
- Свайп через touch-події Chromium CDP на 390 px повторно пройшов для обох галерей після останньої зміни завантаження мініатюр. Це не фізичний Android. `gallery-touch-test.log`.
- Favorites: для товару й запиту перевірено актуальне перше фото, положення сердечка в зображенні, додавання/видалення та відсутність переходу при натисканні. `favorites-1440.png`, `favorites-final.png`.
- Мапа: після розкриття географічних груп перевірено перше фото карток обох типів, вибір товару та запиту і перемикання між двома маркерами через повернення до результатів та зміну масштабу. `map-request-card.png`, `map-product-selected.png`, `map-switch-test.log`.
- Після REVIEW FAIL: повторний Chromium на 1440 px підтвердив головні фото у картках та на мапі, Favorites і перемикання маркерів. Мережа тестових оголошень: 5 запитів мініатюр, 0 запитів оригіналів. `map-card-thumbnail-test.log`, `map-request-card.png`, `map-product-selected.png`.
- Після REVIEW FAIL: touch-перетягування у формах Product і Buy Request на 390 px, активне виділення та відсутність прокрутки сторінки — PASS у Chromium CDP. `touch-drag-test.log`, `product-touch-drag-active-390.png`, `request-touch-drag-active-390.png`.
- Публікація Product і Buy Request через форму з 0 та 8 фото, повторне отримання фото з API — PASS, `publish-qa.log`.
- Редагування обох типів: видалення старого фото, додавання нового і зміна порядку; імітована відповідь 500 не змінює збережені дані, повторне збереження успішне, подвійне натискання створює один PATCH. Product: `edit-errors-qa.log` (цей запуск згодом завершився помилкою підготовки запиту); Buy Request: `edit-request-qa.log`.
- Мережа: для обох оголошень початково запитувався один оригінал; мініатюри запитувалися окремо. Спеціальний прогін із 8 JPEG по 609349 байт: на ширині 320 px до прокручування завантажено 4 мініатюри сумарно 75968 байт, після — 8 сумарно 151936 байт. До і після прокручування завантажено лише один оригінал. Клік останньої мініатюри та збільшення перевірено окремо. `lazy-traffic.json`, `traffic-test.log`, `traffic-320.png`. Це розміри тіл тестових відповідей, не вимірювання реальної мобільної мережі.

## FAIL, які діагностовано

- Перший прогін перетягування не пройшов: браузер запускав штатне перетягування img. Виправлено `draggable={false}`; повторна перевірка пройшла.
- Перший запуск після відновлення інструмента не дочекався `load` за 30 секунд. Локальні frontend/API відповіли 200; trace показав, що холодний Vite повільно віддавав модулі. Повтор після прогріву пройшов перевірки форм і збереження, але зупинився на мапі, де тест не дочекався географічних груп. Окремий сценарій мапи з очікуванням переходів груп пройшов; `map-group-before.png` і `map-district-before.png` зберігають попередні стани.
- Початкова перевірка lazy loading показала завантаження всіх 8 мініатюр до горизонтального прокручування, попри `loading="lazy"`. Додано спостереження видимості в контейнері; повторний мережевий тест пройшов. Дані до виправлення: `lazy-traffic-before.json`.
- Один повторний прогін галереї перервався повідомленням про недоступність сервера: trace зафіксував `net::ERR_NETWORK_CHANGED`, а API — тайм-аут до локального PostgreSQL. Після відновлення з’єднання повторний короткий сценарій пройшов. `gallery-final.log`, `gallery-final-retry.log`.
- Перший touch-прогін після огляду не завершив перестановку: повносторінковий скріншот посеред жесту змінював прокрутку. Після заміни на скріншот видимої області тест пройшов для обох форм.
- Перший запуск тесту публікації зупинився до створення оголошень через відсутню локальну категорію; повтор із наявною категорією пройшов. `publish-qa-before.log`.
- Підготовка Buy Request у першому тесті редагування завершилася 400 через пропущений тестом обов’язковий опис. Product у цьому ж запуску пройшов; повторили лише Buy Request із виправленими тестовими даними.

## UNVERIFIED

- Фізичний Android, фізичний touch та системний мобільний вибір файлів: Chromium використовував емуляцію touch та програмний вибір файлів.
- Фактична затримка завантаження за умов реального мобільного інтернету та поведінка старих зовнішніх URL із великими зображеннями. Для зовнішніх URL власні мініатюри не створюються.
- Окремий live-тест зовнішнього сервісу був пропущений у серверному наборі.
- У сценарії редагування зі змішаними фото початкові оголошення створювалися через API; зміни та збереження виконувалися через браузер.
- Усі шість ширин перевірені до останнього виправлення карток; після нього мапу і Favorites перевірено на 1440 px, touch-перетягування — на 390 px.
