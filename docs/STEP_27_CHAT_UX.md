## Поточна реалізація

- `contextKind` визначає `product`, `request`, `offer`, `deal`, підтверджений `direct` або `unknown`; історичний `type` збережено для сумісності зі Step 26. Невідоме походження не відноситься до прямих.
- Міграція 058 зберігає пару учасників для нових чатів із профілю й персональну межу видимості історії. Для вже видалених чатів межу заповнює з `deleted_at`. Міграція 059 додає необов'язковий ключ запиту, який захищає від дублювання повідомлення та системного сповіщення при повторі.
- Список повідомлень не має пагінації; чинний запит повертає всю видиму учаснику історію. Окрему пагінацію на цьому кроці не додано.
- Показники на вкладках означають кількість чатів; бейджі непрочитаного — кількість повідомлень. Системні сповіщення залишаються окремими від чатового unread.
- Повний backend-набір: 288 passed, 1 skipped. Після наступних серверних виправлень виконано 35 цільових тестів, а після уточнення відкриття видаленого чату угоди — ще один відповідний інтеграційний тест. TypeScript — PASS.
- Playwright/Chromium пройшов основний сценарій і шість розмірів. Підготовка тестових об'єктів через API та фактичні дії в UI розмежовані в [протоколі QA](qa/step-27/README.md). Останнє серверне уточнення для повторного відкриття видаленого чату угоди перевірено інтеграційним тестом; браузерний сценарій після нього повторно не запускався.
