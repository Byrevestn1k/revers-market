# Step 30 — поширення публічного контенту

Статус: готово до незалежного Sol Review. Результати й обмеження перевірок наведені в `docs/qa/step-30/`.

## Механізм

`GET /api/share/:type/:id` формує payload для товару (`product`), запиту (`buy_request`), профілю (`profile`) та відгуку (`review`, з параметром `review`). Інтерфейс отримує payload без cookies. Для запитів дозволені лише стани публічного списку; товар має бути активним. Відгук перевіряється за правилами публічного списку і не містить ID угоди. Дані адреси, телефон і приватні поля профілю не включаються. На кожен запит дані читаються заново.

Прямі маршрути товару, запиту й профілю віддають OG і Twitter metadata в початковому HTML. Для конкретного відгуку використовується `/profiles/:username?review=:id`: сервер формує окремі metadata, а SPA відкриває вкладку відгуків і прокручує до потрібного. Недоступні публічні сторінки віддають безпечну відповідь 404; власник зберігає доступ до власних оголошень. HTML-значення екрануються.

`PUBLIC_ORIGIN` має вказувати origin, який обслуговує сайт, API і публічні uploads. За замовчуванням це `http://localhost:5173`, для публічного середовища потрібен HTTPS origin без шляху. Значення Host не використовується. Публічний сервер або reverse proxy має направляти прямі маршрути `/products/:id`, `/buy-requests/:id`, `/profiles/:username` до Express, а також віддавати frontend assets і `/uploads`. Vite у розробці проксіює ці маршрути. Після появи домену потрібно перевірити реальну конфігурацію маршрутизації, доступність зображень, MIME, TLS та crawler-и.

Головне фото з локальних uploads або безпечний HTTPS URL використовується для preview, інакше — `/brand/logo-mini.png`. Публічний аватар, який зберігається як data URL, видається як зображення через `/api/share-avatar/:username` з перевіркою формату. Нові копії зображень не створюються. Перенесення файлів у нове сховище не виконувалося.

Платформи можуть зберігати власний кеш preview навіть після зміни або закриття оголошення. Доступність зовнішнього фото за відсутності cookies залежить від сервера, який його розміщує; це потрібно перевірити після запуску публічного домену.

Меню пропонує Telegram, Viber, Facebook, копіювання посилання й тексту та системне меню за наявності Web Share API. Instagram може бути доступний як отримувач системного меню; також можна скопіювати текст або посилання. Сайт не створює автоматично пост або Stories і не знає, чи користувач завершив публікацію. Доступність Viber залежить від пристрою; копіювання залишається альтернативою. Скасування системного меню не показує повідомлення про успіх.

Повний backend-набір пройшов до останніх точкових виправлень; після них пройшли цільові тести, TypeScript і Chromium. Детальні результати та обмеження — у [QA-протоколі](qa/step-30/README.md). Нових міграцій немає; основна база, deployment, merge та push не використовувалися.
