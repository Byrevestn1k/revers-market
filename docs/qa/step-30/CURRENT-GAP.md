# Step 30: попередній аудит

Статус: аудит розпочато, реалізацію і перевірки ще не завершено.

## CURRENT

- SPA використовує адреси `/products/:id`, `/buy-requests/:id` і `/profiles/:username`.
- Детальний публічний API товару без авторизації повертає тільки товар зі статусом `active`.
- Публічний список запитів обмежений станами `open`, `partially_selected`, `partially_completed`, `partially_fulfilled`. Детальний API запиту без авторизації відхиляє лише `cancelled`, тобто має ширші правила.
- Публічний список відгуків виключає неопубліковані та відгуки зі скасованих угод і перевіряє ролі учасників. Відповідь містить `orderId`, який не повинен потрапити у share payload чи metadata.
- Публічний профіль має окремі рейтинги продавця й покупця; доступність телефона залежить від налаштувань приватності та авторизації.
- Backend віддає локальні файли `/uploads`; Vite проксіює `/api` і `/uploads`. Початковий `frontend/index.html` містить загальні metadata; Express наразі не віддає HTML SPA.

## GAP

- Потрібен спільний payload на основі лише публічних полів, з додатковою перевіркою активного стану запиту і без даних угоди.
- Потрібні початкові HTML metadata та перевірена конфігурація публічного origin; зміна тегів лише в браузері не забезпечить preview для crawler-ів.
- Потрібні адреса конкретного публічного відгуку, відкриття відповідної вкладки і прокручування до нього.
- Потрібні меню поширення, доступне копіювання, підтримувані канали та fallback, а також перевірка всіх заданих розмірів екрана.
- Потрібні тести приватності, metadata, payload та Browser QA. Зовнішні preview потребують окремої перевірки після появи публічного HTTPS origin.
