# Step 31 — PWA та Web Push

Базовий коміт: `72977ee9f5fc591039b0eb023482fcb5021bed3b`. Цей документ описує доповнення до наявного маркетплейсу, а не окремий мобільний застосунок.

Manifest задає назву «ДещоТреба», режим `standalone` та іконки. Запрошення до встановлення можна відхилити і відкрити з меню знову. У сумісному браузері використовується системний запит; для iPhone показано інструкцію. Service Worker кешує лише визначені публічні статичні файли та offline-сторінку; API і HTML-навігація не кешуються. Оновлення очікує завершення використання старого worker і не перезавантажує відкриту форму.

Push використовує наявні події центру сповіщень. Текст push не містить тексту листування, адрес чи умов угоди. Дозвіл запитується за дією користувача; звичайний центр сповіщень працює без нього. Підписка пов'язана з користувачем і його сесією, а після виходу чи заміни сесії відкликається. Черга записується в тій самій транзакції, що й подія. Відправлення робиться не більше одного разу: при невизначеній мережевій помилці подія залишається доступною в центрі сповіщень, але push може бути втрачено.

## Конфігурація

Для Web Push потрібні `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` та `VAPID_SUBJECT` у середовищі сервера. Створюйте окрему пару ключів для кожного середовища; приватний ключ не зберігайте в Git. Якщо налаштувань немає, push недоступний, а внутрішні сповіщення продовжують працювати. Міграція `063_web_push.sql` потребує застосування перед запуском нового коду. Її перевірка та стан огляду описуються в QA-протоколі.
