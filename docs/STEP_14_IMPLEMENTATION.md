# Step 14: способи отримання та географічна сумісність

## Модель

Нові Product, Buy Request і підписки зберігають кілька `deliveryOptions`. Продавець обирає територію окремо для кожного способу. Seller Offer підтверджує один фактичний спосіб, доступний у пов'язаному Product, або задає його вручну. Старі поля API залишаються для сумісності зі старими клієнтами.

| Спосіб | Умови покупця | Умови продавця |
| --- | --- | --- |
| `SELF_PICKUP` | Радіус від місця покупця або область | Місце самовивозу |
| `SELLER_DELIVERY` | Місце отримання | Радіус від місця продавця або перелік областей |
| `POSTAL_DELIVERY` | Область отримання | Уся Україна або перелік областей |
| `FLEXIBLE` | Готовність домовлятися | Готовність домовлятися |

Сервер повертає `EXACT_MATCH` лише для спільного конкретного способу із сумісною територією. `FLEXIBLE` може дати `POSSIBLE_AGREEMENT`. Відомі несумісні умови дають `NO_MATCH`; відсутні дані дають `UNKNOWN`. Радіуси рахуються як географічна відстань, а не як відстань дорогою. Публічне округлення координат створює похибку; біля межі радіуса відповідь лишається `UNKNOWN`.

Міграція `046_delivery_options.sql` додає nullable JSONB поля. Вона не приписує старим записам радіус, область чи поштову доставку. Записи без уточнених умов залишаються в каталозі, а відповідь щодо їх доставки консервативно є `UNKNOWN`. Історичний snapshot Deal не перераховується після зміни Product чи Request. Зміна істотних умов Request після появи Offer або Deal блокується сервером з HTTP 409.

Підписки Step 8 використовують ті самі категорію, географію, кількість і бюджет. Автоматичне сповіщення про новий Request створюється тільки за `EXACT_MATCH` доставки та решти критеріїв; кілька сумісних способів не створюють дублікати. Request без бюджету не відхиляється через мінімальну ціну в підписці. Старі підписки можна поступово уточнити в редакторі. Майбутнє налаштування «Повідомляти також про можливі домовленості» можна додати окремо; зараз воно не вмикається автоматично.

Точні приватні адреси не використовуються як публічні точки сумісності. Поштові служби, тарифи, платіж на платформі й маршрути не інтегровані.

Звичайний пошук на мапі показує всі оголошення, доки користувач сам не обере фільтр способу отримання. Фільтр перевіряє лише заявлений спосіб, а не підтверджену сумісність із конкретним користувачем. Старі записи фільтруються за їхнім старим позначенням способу, без вигадування географічних обмежень.
